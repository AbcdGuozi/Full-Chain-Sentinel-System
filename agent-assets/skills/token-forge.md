# 令牌伪造

## 1. 先解析

记录 header、payload、签名算法、`kid`、`jku`、`x5u`、签发者、受众、过期时间和自定义权限字段。不要修改真实用户数据，使用测试账号。

## 2. 常见验证顺序

1. `alg: none`：去掉签名，观察服务端是否仍接受。
2. `RS256 -> HS256`：用公钥当作 HMAC 密钥重签。
3. `kid` 注入：路径穿越、SQL 片段、命令片段或指向可控文件。
4. `jku` / `x5u`：指向自有测试 JWKS，观察是否拉取并信任。
5. 离线弱密钥：用本地字典尝试 HMAC 密钥，最多 5 次；不做在线登录爆破。
6. claims 替换：只替换测试账号的 `sub`、`userId`、`role`、`tenant` 等字段，观察越权。

## 3. 判据

- 伪造令牌返回 200 且能访问仅测试账号可见的对象，才算确认。
- 401/403 或跳转登录页不算成功。
- 只验证一个对象和一个字段，不批量枚举。

## 4. 停止条件

- 需要修改真实用户密码、绑定手机号或删除数据时停止。
- 在线爆破超过 5 次立即停止。
- 伪造令牌只用于确认漏洞，不用于持久化访问。

## 5. 上报

提交原始 JWT header/payload、伪造方式、对照请求、响应差异和修复建议。令牌中的真实签名密钥不写入报告。
