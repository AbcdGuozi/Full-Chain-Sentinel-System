# WAF 绕过变形（已授权静态模板）

本文件服务于**已授权测试中的模板选型与变形**。发送由受控工具按任务执行；所有模板先替换占位符，按范围执行到确认漏洞存在即停止，不持久化、不扩大影响。

机器可读模板通过 由 `payload_get` 返回的 `bypassVariants` 提供；目录中的静态副本位于 `payload-catalog.json` 的 `bypassVariants` 字段。生成结果只是候选，不是漏洞结论。

## 适用前提

1. **已授权**：目标、路径、方法、时间窗和测试账号均在书面范围内；没有授权时停止。
2. **先基线后变形**：先用原始无害值记录状态码、响应长度、关键响应头、响应体摘要和耗时；没有基线就不判断“被拦截”或“被绕过”。
3. **一次只改一个维度**：一次只改编码、大小写、注释、空白或结构中的一个因素；不要同时叠加多层编码和结构变形，否则无法归因。
4. **最小影响**：优先使用 `id`、`whoami`、`cat <FILE>` 等只读探针；需要上传时只上传最小验证文件，不写持久化 webshell、不删数据、不反弹 shell。
5. **占位符与真实值**：模板中的 `<TARGET>`、`<FILE>`、`<PARAM>` 等占位符必须按当前目标和范围替换；不得写入真实账号、Token、Cookie、个人数据或客户信息。发送前确认闭合上下文和停止条件。

## 推荐变形顺序

按“先轻后重、先传输后语法”的顺序逐项验证；每一步都保留 `decodeSteps`，说明接收端可能如何还原：

1. **URL 编码**：只改变传输编码，确认解码发生在过滤前还是过滤后。
2. **双重 URL 编码**：确认是否存在重复解码；一次解码通常只还原到单次编码形式。
3. **大小写/空白替代**：SQL 关键字大小写、`%09`、`%0a`、`+`；只对大小写或空白不敏感的解析器成立。
4. **SQL 注释**：`/**/` 与 `/*!50000...*/` 只用于 MySQL 只读探针；关键字和闭合结构必须仍然可读。
5. **路径穿越专用变形**：依次观察 `....//....//`、`..//..//`、`..%2f..%2f`、`%252e%252e%252f`；每一步都依赖不同的归一化顺序，不能混为一谈。
6. **XSS 编码变形**：实体、十六进制实体和大小写混写只改变表达方式；Unicode 转义只适用于对应解析上下文，全角字符只用于观察 NFKC 归一化，通常不能直接执行。
7. **命令注入分隔符**：在分号、管道、`&&`、`%0a`、`%09` 之间逐项切换；`$IFS` 和 `{cat,<FILE>}` 只用于 `cat <FILE>` 等只读文件探针。
8. **上传扩展名**：只改变最小验证文件的扩展名表达方式（大小写、双扩展名、点号编码、尾随点）；确认可访问或可解析后停止，不写持久化 webshell，不覆盖已有文件。
9. **历史兼容项放最后**：空字节截断 `%00` 只作为旧系统兼容示例；现代 PHP 5.3.4+ 已不再接受 `%00` 截断，不能据此判断现代环境。

变形不是“越多越好”。如果某个维度没有基线差异，记录否定结果并停止该维度，不要继续堆叠编码。

## 如何判断 WAF 拦截

先固定请求方法、路径、参数位置、身份和测试数据，再与基线做差分。至少观察以下信号：

- **状态码**：基线为 `2xx`，变形后稳定出现 `403`、`406`、`429` 或其他异常状态；注意有些 WAF 仍返回 `200`。
- **响应页**：出现通用拦截页、验证码页、挑战页、明显的规则编号或统一短文本；只记录脱敏特征，不复制页面中的真实信息。
- **响应长度与结构**：长度突然显著缩短、关键字段消失、返回结构从业务数据变成错误页；与同一接口的基线长度比较，而不是只看绝对值。
- **延时**：出现稳定的额外延时（例如约 2-5 秒）且可重复；排除网络抖动、数据库慢查询和连接池告警后再判断。
- **响应头与连接行为**：新增拦截标识、连接被重置、TLS/网关错误等；只记录头名和脱敏值。
- **对照请求**：同一时刻发送原始无害值和变形值；两次结果不同才说明该维度可能被处理，不能把单次差异直接归因于 WAF。

判定时至少保留：请求方法、脱敏后的路径和参数位置、状态码、响应长度、耗时、时间、基线/测试对照和结论。不要把完整响应体、Cookie、Token 或个人数据写入共享知识库。

## 停止条件

出现以下任一情况，立即停止该维度或整个测试，不自动重试、不换更多绕过参数：

- 同一维度连续出现 `403`、`406` 或 `429`（例如连续 3 次），或拦截页/验证码持续出现。
- 触发告警、封禁、账号锁定、风控、审计通知或联系人反馈。
- 出现写入副作用：文件创建/覆盖、数据新增/修改/删除、配置变化、队列消息、邮件/短信、权限变化。
- 出现持久化迹象：计划任务、启动项、注册表、`authorized_keys`、服务启用等。
- 出现反向连接、下载执行、交互式 shell 或命令执行副作用。
- 响应开始返回真实个人信息、密钥、Token、业务数据或超出授权范围的内容。
- 出现无法解释的 `5xx`、连接池/慢查询告警、服务不稳定或明显资源消耗。
- 端点语义不清、可能是写接口、需要跨越授权边界，或无法确认模板中的占位符会落到什么上下文。

停止时记录“触发条件 + 最小必要证据 + 待复核结论”，不要为了得到“已绕过”的结论继续尝试。

## 变形不是免死金牌

- WAF 可能只检查原始字符串，也可能在业务层多次解码；编码成功不等于业务语义成功。
- 实体编码、全角字符、Unicode 转义可能只让字符串通过规则，却不会在目标上下文中执行；必须区分“未被拦截”和“可利用”。
- 静态模板和本地测试不能证明线上目标存在漏洞；没有授权或超出当前目标时，不能把候选模板当成攻击指令。
- 不写入特定 WAF 产品的私有绕过参数、规则编号或真实目标；不使用自动扫描、爆破、批量枚举或持久化。
- 任何一次变形都应可复现、可解释、可回滚；无法解释的差异按“待复核”处理，不按成功处理。

## 模板字段与目录维护

`payload_get` 返回的 `bypassVariants` 使用以下字段：

- `id`：稳定标识；
- `technique`：变形技术；
- `template`：脱敏后的静态模板，只使用 `<TARGET>`、`<FILE>`、`<PARAM>` 等占位符；
- `decodeSteps`：接收端可能如何逐层还原；
- `risk`：`low`、`medium` 或 `high`；
- `note`：语义边界和失败条件；
- `applicableWhen`：只在该上下文下才有讨论价值。

更新目录后重新运行 `payload_search` 验证条目能被检索；只新增字段，不改既有条目。
