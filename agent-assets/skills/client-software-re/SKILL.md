# Windows 客户端软件逆向方法论

本文从一份授权的医疗行业客户端软件安全测试报告中提炼**方法**，不保留该报告的机构、主机、地址、账号、口令、数据库名、日志样本或利用结果。文中出现的工具名、文件类型和函数名用于说明分析路径，不代表任何当前目标。

适用范围：已授权的 Windows 胖客户端（PowerBuilder、.NET、Delphi/C++、Electron 等），在隔离实验环境或专用测试终端上进行。目标不是“拿到凭据并连库”，而是证明**敏感信息以何种形式暴露、暴露面到哪里、证据是否充分**。

上级边界：[non-destructive-testing.md](../non-destructive-testing.md)。数据库写操作、命令执行、配置修改、横向移动、批量导出均不在本文范围。

## 1. 总体路径

| 阶段 | 问题 | 方法 | 产出 | 停止条件 |
|---|---|---|---|---|
| 0 授权 | 能否分析这个客户端和这台测试机 | 核对资产、版本、测试账号、时间窗 | 资产标识与环境基线 | 资产/设备归属不明 |
| 1 静态基线 | 它是什么技术栈、是否加壳、依赖什么 | 哈希、签名、PE 头、导入表、字符串 | 技术栈与依赖清单 | 需要脱壳才能继续 |
| 2 文件行为 | 启动时读了哪些配置和库 | Process Monitor 过滤 | 文件/注册表访问路径 | 捕获到真实用户数据 |
| 3 配置审阅 | 配置是否含连接串/口令 | 定位加载点与解码函数 | 字段名、存储形式、是否可逆 | 需要输出明文口令 |
| 4 内存观察 | 运行时是否出现敏感字段 | 受控调试器/内存搜索 | 字段类别与模块/偏移 | 需要 dump 生产进程 |
| 5 协议识别 | 通信是否加密、用什么协议 | 抓包 + 协议特征 | 协议、端口类别、TLS 状态 | 报文含真实凭据/PII |
| 6 结论 | 风险如何定性、如何修复 | 证据交叉验证 | 暴露面与修复建议 | 需要连库或执行命令才能“证明” |

核心原则：**只记录证据，不导出真实数据；不在生产改配置；不用恢复的凭据登录任何系统。**

## 2. 静态基线：先判断技术栈

```powershell
# 文件身份与签名
Get-FileHash .\client.exe -Algorithm SHA256
sigcheck -a -q client.exe

# PE 结构与安全编译选项（需 Visual Studio 开发人员命令提示符）
dumpbin /headers client.exe | Select-String -Pattern 'machine|subsystem|DLL characteristics'
dumpbin /imports client.exe | Select-String -Pattern 'pbvm|sql|ssl|crypto|wininet|winhttp'

# 依赖与加载顺序（图形工具）
# Dependencies.exe / Dependency Walker：只读打开，不替换 DLL
```

| 线索 | 可能技术栈 | 怎么验证 | 证据 | 什么时候停 |
|---|---|---|---|---|
| 导入 `pbvm*.dll` | PowerBuilder | 版本号、同目录 PBD 文件 | 运行时版本、PBD 清单 | 需要反编译 PBD |
| 大量 `mscorlib`/`System.*` | .NET | `dnSpy` 只读加载，查看程序集与模块 | 程序集名、目标框架 | 需要调试生产进程 |
| `Qt5*.dll`、`vcruntime` | C++/Qt | 导入表、字符串、资源 | 框架与版本 | 需要脱壳 |
| `app.asar`、`Electron` | Electron | 解包 `resources/app.asar`（本地副本） | 主进程入口与依赖 | 包含真实令牌 |
| 区段高熵、导入极少 | 加壳/混淆 | 区段熵、入口点、字符串可读性 | 壳特征与影响 | 需要脱壳 |

`Get-PESecurity` 可检查 ASLR、DEP、CFG、SafeSEH 等编译选项。这类结果属于“加固建议”证据，不是漏洞本身；不要因为缺少某个选项就直接定级。

### 2.1 PowerBuilder 线索

- PBD 是 PowerBuilder 的动态库/编译单元，运行时由 `pbvm*.dll` 加载。
- 反编译工具（如 `shudepb`）可恢复对象、函数、数据窗口和部分源码结构；输出是近似结果，需要与运行时行为交叉验证。
- 关注：数据库连接参数、解码/加密函数、SQL 拼接、外部命令调用、文件路径、日志写入。
- 函数名可能保留业务语义（如 `gf_*` 全局函数）；先用字符串和交叉引用定位，不要盲扫全部 PBD。

验证：PBD 清单 + 运行时模块加载记录 + 反编译函数签名三者一致。
证据：PBD 文件名、函数名、调用者、参数类型；不贴完整反编译源码。
什么时候停：反编译需要绕过授权/加密保护，或输出包含生产凭据。

### 2.2 .NET 线索

- `dnSpy`/`ILSpy` 可只读加载程序集，查看命名空间、类、方法和资源。
- 调试会附加进程并可能改变时序；生产环境不调试。
- 关注 `app.config`/`*.exe.config`、`ConnectionString`、`ProtectedData`、`appsettings.json`、嵌入资源、`AssemblyInfo`。
- 混淆（ConfuserEx 等）会破坏反编译；只记录“存在混淆”，不提供脱壳。

## 3. Process Monitor：看它启动时读了什么

只对**单个客户端进程**做短时捕获，避免全系统长期记录（会产生大量无关路径和用户信息）。

建议过滤条件（在 GUI 的 Filter 中设置）：

```text
Process Name is client.exe
Operation is ReadFile
Path contains .pbd        # 或 .set / .config / .ini / .json
Result is SUCCESS
```

补充：

```text
Operation is Load Image
Path contains .dll
```

| 要确认 | 怎么验证 | 证据 | 什么时候停 |
|---|---|---|---|
| 配置文件路径 | ProcMon 的 `Path` 列，排除系统目录 | 相对安装目录的路径 | 路径指向用户私人目录 |
| 读取顺序 | 时间列 + `Detail` 列 | 首次读取、重复读取、失败后回退 | 需要修改文件才能触发 |
| 加载的运行时 | `Load Image` 事件 | DLL 名与版本 | 需要替换 DLL |
| 配置是否可写 | 文件 ACL / 目录权限（只读查看） | 是否普通用户可写 | 需要实际写入验证 |
| 是否有临时解密文件 | 启动后目录新增文件 | 文件名、生命周期 | 文件含明文凭据 |

证据处理：导出 CSV 后删除用户名、主机名、盘符中的个人信息，只保留安装目录相对路径。ProcMon 的 `.pml` 原始文件可能含敏感路径，按证据保留策略加密保存，不进入共享知识库。

**不在生产机改配置。** 需要验证“改配置会怎样”时，只在隔离实验环境的副本上做，并由所有者提供测试配置。

## 4. 字符串与配置文件

### 4.1 字符串搜索

```powershell
# Sysinternals strings；先统计，不直接把全部命中打到终端
strings64.exe -n 8 client.exe | Select-String -Pattern 'password|passwd|pwd|connection|server|database|integrated security' | Measure-Object

# 只在隔离目录查看单条命中，报告只写类别与偏移
strings64.exe -n 8 client.exe > strings.txt
```

| 目标 | 线索 | 证据 | 停止条件 |
|---|---|---|---|
| 连接串 | `Data Source`、`Initial Catalog`、`User ID`、`Provider` | 键名、是否明文、所在模块 | 出现明文口令 |
| 加密/编码函数 | `Encrypt`、`Decrypt`、`Base64`、`Crypto` | 函数名、调用者 | 需要复现解密 |
| 外部命令 | `cmd.exe`、`powershell`、`CreateProcess` | 调用点与参数来源 | 需要实际执行 |
| 日志路径 | `log`、`trace`、`*.log` | 路径与写入内容类别 | 日志含真实 PII |
| 更新/下载 | `http://`、`https://`、`update` | 端点类别、是否校验签名 | 需要访问真实更新源 |

字符串命中经常是误报（库函数名、错误提示）。结论至少要满足“字符串 + 调用点/配置读取 + 运行时行为”中的两项。

### 4.2 配置文件解密

报告中的路径是：配置文件直接打开为乱码 → 定位解码函数 → 复现算法 → 得到连接凭据。通用做法：

1. **定位加载点**：ProcMon 确认客户端读取了哪个配置文件（`.set`、`.ini`、`.config`、`.json`）。
2. **定位解码函数**：在反编译/反汇编中搜索文件名、配置键、错误提示，沿交叉引用找到读取与解码调用。
3. **判断算法类型**：逐字节变换、异或、定长抽取、Base64、压缩、标准加密库调用。只记录类别与参数规模。
4. **在副本上验证**：把配置文件复制到隔离目录，用测试配置验证“输入→输出”关系；不要对生产共享目录中的原文件运行脚本。
5. **最小化输出**：只记录字段名、字段长度、是否可逆、是否明文；不把解出的口令、连接串、库名写入报告或聊天记录。

```bash
# 只看文件头与结构，不打印全文
file database.set
xxd -l 64 database.set
```

| 判断 | 怎么验证 | 证据 | 什么时候停 |
|---|---|---|---|
| 是弱混淆而非强加密 | 单字节变换、固定步长、无密钥材料 | 变换类别、可逆性 | 需要输出明文 |
| 使用标准加密 | 导入 `Crypt*`/OpenSSL/`AES`，有 IV/Key 派生 | 算法、模式、密钥来源类别 | 需要导出密钥 |
| 配置含连接凭据 | 解码后出现连接串结构 | 字段名、口令长度、是否明文 | 已确认即可停，不记录值 |
| 配置可被普通用户读取 | 文件 ACL、安装目录权限 | 可读主体类别 | 需要提权验证 |

**关键边界**：确认“配置中存在可解密的数据库凭据”已经足够定性。不要用该凭据登录数据库，不要执行系统命令、写表或导出数据。报告建议应写“改为非对称加密/系统凭据库、限制文件权限、轮换凭据”，而不是复述利用链。

## 5. 内存观察与 dump

运行时内存可能同时存在解密后的连接串、口令、令牌和 PII。只在授权测试终端、测试账号、合成数据会话下进行。

```powershell
# 先看进程与模块，不 dump
Get-Process client | Select-Object Id, Path, StartTime
Get-Process client | Select-Object -ExpandProperty Modules |
  Select-Object ModuleName, FileName | Format-Table
```

| 方法 | 适用 | 证据 | 风险控制 |
|---|---|---|---|
| 调试器字符串搜索 | 已知关键字段、短时观察 | 模块、偏移、字段类别 | 不用生产进程；不修改内存 |
| 进程 dump + `strings` | 需要离线复核 | dump 哈希、命中类别 | 全量 dump 含 PII；加密保存、按策略处置 |
| WinDbg `s -a` 搜索 | 需要地址空间上下文 | 地址范围、模块归属 | 不把命中值贴出 |

```powershell
# 仅在隔离实验环境、合成数据会话中使用
procdump -ma <pid> client.dmp
Get-FileHash .\client.dmp -Algorithm SHA256
```

dump 不是“只读证据”的默认选项：它会把当时进程内的所有数据复制到磁盘。必须满足：所有者授权、终端全盘加密、访问受控、留存期限明确、分析完成后按数据处置策略销毁。报告中只写“在模块 X 的地址范围发现字段类别 Y”，不写具体值。

若只需要确认“是否存在明文口令”，优先用受控调试器的字符串搜索；dump 是最后手段。

## 6. 协议识别与抓包

报告的线索是：客户端与数据库之间使用明文协议，抓包可直接看到登录过程；端口是协议判断的辅助证据，不是唯一证据。

```bash
# 列出接口，确认抓包网卡
tshark -D

# 仅抓授权测试主机与指定端口，限制文件大小与时长
tshark -i <iface> -f "host <lab-host> and tcp port <port>" -w capture.pcapng

# 只看元数据，不打印报文内容
tshark -r capture.pcapng -T fields -e frame.number -e ip.src -e ip.dst -e tcp.srcport -e tcp.dstport | head
```

| 要确认 | 怎么验证 | 证据 | 什么时候停 |
|---|---|---|---|
| 协议类型 | 端口 + 握手特征 + 报文结构；MSSQL/TDS 有固定包头与预登录阶段 | 协议名、端口类别、证据包号 | 需要解析认证报文 |
| 是否 TLS | 握手记录、`TLS ClientHello`、证书交换 | 是否加密、TLS 版本 | 需要导入信任锚 |
| 是否明文凭据 | 登录阶段是否出现可读的用户名/库名 | 只记“存在明文认证字段” | 已确认即停，不复制报文 |
| 会话是否可重放 | 不重放；只做静态判断 | 是否有随机数/挑战 | 需要重放才能证明 |

报告用抓包确认了“数据库通信未加密”。这类结论的证据是“在授权测试会话中观察到协议明文”，不是“端口是 1433 所以一定明文”。抓到认证报文后立即停止保存完整流，保留包号、时间、协议字段类别即可；原始 pcap 含凭据，按敏感证据管理。

## 7. 数据库客户端与命令执行：取证边界

报告在获得数据库凭据后，进一步通过数据库客户端执行了系统命令，证明了主机控制权。这个动作**不属于本文允许的验证方式**，也不应复制。

| 诱惑 | 为什么不做 | 替代证据 |
|---|---|---|
| 用恢复的凭据登录数据库 | 会建立真实会话、可能触发审计/锁账号、扩大影响 | 配置文件/内存中凭据存在性 + 权限可读性 |
| 查询用户表验证数据 | 读取真实 PII，超出最小证据 | 表结构/权限配置的静态证据 |
| 执行系统命令 | 改变主机状态、可能留痕、属于利用 | 报告“凭据可导致数据库权限暴露”，建议轮换 |
| 开启数据库的命令执行扩展或提升权限 | 修改数据库配置，破坏性 | 不建议验证；按高危暴露处置 |
| 导出数据库/批量查询 | 数据外流 | 只统计“可访问对象类别”，不导出 |

只有当所有者**另行书面授权**、提供只读测试账号、明确测试库和回滚方案时，才可能在隔离环境做最小化连通性验证；即便如此也不执行写操作或系统命令。默认结论停在“凭据暴露”，把“可能导致主机控制”写在影响分析中，而不是通过实测证明。

## 9. 日志与敏感信息审阅

| 检查点 | 怎么验证 | 证据 | 什么时候停 |
|---|---|---|---|
| 日志是否记录认证信息 | 搜索日志字段名、查看测试账号登录后的日志类别 | 字段名、是否脱敏 | 出现真实凭据 |
| 是否记录 PII | 用合成数据触发；只统计字段类别 | 字段类别、条数级别 | 出现真实 PII |
| 日志权限 | 文件 ACL、目录权限 | 可读主体类别 | 需要提权读取 |
| 日志轮转/留存 | 配置与文件列表 | 留存天数、是否加密 | 需要修改配置 |
| 客户端本地缓存 | 安装目录/用户目录中的 `.log`、`.tmp`、`.cache` | 路径与内容类别 | 需要导出真实数据 |

报告把“日志保留手机号、身份证号”定为低危。定性时区分：日志是否可被低权限用户读取、是否随支持包外发、是否长期留存。仅“日志里有 PII”不足以判断影响，仍需访问路径证据。

## 10. 证据模板与停止条件

```text
资产：<授权编号> / <客户端名称与版本> / <安装包 SHA-256>
环境：<Windows 版本> / <隔离实验机或测试终端> / <测试账号标签>
工具：Process Monitor <版本> / IDA <版本> / strings <版本> / tshark <版本>
观察：<配置文件相对路径> 在启动阶段被读取；解码函数 <名称>；字段类别 <连接凭据>
方法：静态导入表 + 文件行为 + 副本解码验证；未连接数据库、未执行命令
证据：<脱敏路径> / <字段名与长度> / <pcap 包号与协议字段>
结论：已确认 / 待复核 / 未验证
停止点：<已确认凭据暴露，未进一步登录；或需要输出明文/改配置而停止>
```

立即停止：

- 需要改生产配置、替换 DLL、写入安装目录。
- 需要输出或共享明文口令、完整连接串、密钥。
- 需要登录数据库、执行 SQL/系统命令、导出数据。
- 抓到真实用户凭据/PII，且无法在不保留原文的情况下说明问题。
- 目标主机不是授权测试终端，或客户端连接的是生产库。
